홈페이지 유지보수 계약은 월 금액이 얼마인지보다, 그 금액으로 무엇을 어디까지 해 주고 문제가 생기면 얼마나 빨리 움직이는지가 계약서에 적혀 있는지로 판단해야 합니다. 볼 항목은 수정 범위, 보안·백업, 호스팅·도메인 갱신, 장애 대응 시간, 계약이 끝날 때 넘겨받을 자료입니다. 이 중 하나라도 "협의"라는 한 단어로만 적혀 있다면 서명 전에 구체적인 문구로 채워 달라고 요청하세요.

## 유지보수 문제는 대개 오픈하고 한참 뒤에 드러납니다

오픈 직후에는 연락도 빠르고 수정도 금방 됩니다. 문제는 1년쯤 지나서 생깁니다. 직원 사진 한 장을 바꾸려는데 "그건 디자인 변경이라 별도 비용입니다"라는 답을 듣거나, 어느 날 아침 홈페이지가 열리지 않아 알아보니 도메인 기간이 끝나 있었다는 식입니다. 둘 다 계약서에 한 줄만 있었어도 피할 수 있었던 일입니다.

제작 단계의 견적은 [홈페이지 제작 비용, 견적서에서 금액이 갈리는 항목](/insights/homepage-build-cost-quote/)에서 다뤘고, 여기서는 오픈 이후의 관리 계약만 봅니다.

## 1. 수정은 몇 번보다 어디까지인지

"월 2회 수정"처럼 횟수만 적힌 계약서가 많습니다. 실제로 말이 엇갈리는 지점은 횟수가 아니라 범위입니다.

| 구분 | 예시 | 계약서에서 확인할 것 |
|---|---|---|
| 단순 수정 | 문구, 전화번호, 사진 교체 | 월 횟수 안에 포함되는지 |
| 콘텐츠 추가 | 공지·사례 글 등록, 메뉴 항목 추가 | 글 단위로 세는지, 페이지 단위로 세는지 |
| 기능·디자인 변경 | 새 페이지 구성, 레이아웃 변경, 예약 기능 추가 | 별도 견적인지, 단가 기준이 적혀 있는지 |

요청 방법과 처리 기한도 같이 적혀 있어야 합니다. 단톡방이나 메일로 요청하면 영업일 기준 며칠 안에 반영하는지, 그달에 쓰지 않은 횟수가 다음 달로 넘어가는지까지 정해 두면 나중에 서로 기억이 다를 일이 없습니다.

## 2. 보안 업데이트와 백업은 누가, 얼마나 자주

설치형 관리 프로그램(CMS)으로 만든 홈페이지는 프로그램과 플러그인 업데이트를 미루면 보안 취약점이 생깁니다. 업데이트를 누가 언제 하는지가 계약서에 없으면, 사고가 난 뒤에야 서로 상대가 하는 줄 알았다는 이야기가 나옵니다.

백업도 "백업해 드립니다"보다 구체적인 문장이 필요합니다.

- 백업 주기: 매일인지, 주 1회인지
- 보관 위치: 같은 서버에만 두면 서버 장애 때 백업도 함께 사라질 수 있음
- 보관 기간과 복구 요청 시 처리 방법, 비용
- 상담폼으로 받은 고객 정보를 어디에, 언제까지 보관하는지

## 3. 호스팅·도메인·보안 인증서는 명의와 갱신일부터

가장 자주 놓치는 항목입니다. 누구 명의인지, 갱신은 누가 언제 하는지, 비용이 월 유지보수비에 들어 있는지 따로 내는지를 표로 받아 두세요.

| 항목 | 확인할 것 |
|---|---|
| 도메인 | 등록 명의(회사 명의 권장), 만료일, 자동 갱신 여부 |
| 호스팅(서버) | 계약 명의, 사양을 올릴 때 비용, 접속이 몰릴 때 처리 방식 |
| 보안 인증서(SSL) | 갱신 주체, 만료 알림을 받는 사람 |
| 관리자 계정 | 우리 회사가 최고 관리자 권한을 갖고 있는지 |

도메인이 대행사 명의로 등록돼 있으면 계약을 끝낼 때 상대의 협조가 있어야 주소를 옮길 수 있습니다. 같은 문제가 광고 계정에서도 생기는데, [온라인광고대행사 계약서 점검 항목](/insights/online-ad-agency-contract-checklist/)에서 함께 다뤘습니다.

## 4. 장애 대응은 접수 시간과 복구 시간을 나눠서

"장애 시 신속 대응"은 사실 아무것도 정하지 않은 문장입니다. 사이트가 열리지 않거나 상담폼이 작동하지 않는 상황을 기준으로 다음을 적어 두세요.

1. 접수 채널: 전화, 단톡방, 메일 중 무엇으로 알리는지
2. 응답 시간: 접수 후 몇 시간 안에 원인 확인을 시작하는지
3. 복구 목표: 원인별로 언제까지 정상화하는지
4. 야간·주말: 다음 영업일 처리인지, 긴급 연락처가 따로 있는지
5. 결과 공유: 원인과 조치 내용을 어떤 형태로 알려 주는지

홈페이지로 예약이나 상담을 받는 업종이라면 상담폼이 멈춘 하루가 그대로 놓친 문의가 됩니다. 응답 시간만큼은 시간 단위 숫자로 받아 두시기 바랍니다.

## 5. 계약이 끝날 때 넘겨받을 것

업체를 바꾸거나 직접 관리하게 될 때를 대비해 인계 목록을 계약서에 넣어 둡니다.

- 홈페이지 파일과 데이터베이스 전체 백업본
- 관리자·호스팅·도메인 계정 정보
- 디자인 원본 파일과 사진 원본
- 유료 글꼴·이미지·플러그인 라이선스가 누구 명의인지
- 결과물의 저작권과 소유권이 누구에게 있는지

마지막 두 가지는 제작 계약서에 적혀 있는 경우가 많으니, 제작 계약서와 유지보수 계약서를 나란히 놓고 보세요. 유료 이미지를 제작사 명의로 샀다면 계약이 끝난 뒤에도 그 이미지를 계속 써도 되는지 따져 봐야 합니다.

## 견적서 두 장을 놓고 비교할 때

월 금액이 비슷해도 들어 있는 항목이 다르면 같은 상품이 아닙니다. 견적서에서 아래 칸이 비어 있다면 오른쪽 질문을 그대로 물어보시면 됩니다.

| 항목 | 비어 있을 때 물어볼 말 |
|---|---|
| 수정 범위와 횟수 | "사진 교체와 새 페이지 추가는 각각 어떻게 세나요?" |
| 보안 업데이트·백업 | "백업은 어디에 두고, 복구는 며칠 걸리나요?" |
| 호스팅·도메인·SSL | "갱신 비용은 이 금액에 들어 있나요, 명의는 누구인가요?" |
| 장애 대응 | "주말에 사이트가 멈추면 언제 연락이 오나요?" |
| 보고 | "한 달에 무엇을 했는지 어떤 형태로 받을 수 있나요?" |
| 계약 기간·해지 | "중간에 그만두면 무엇을 넘겨받나요?" |

지금 홈페이지가 오래돼서 고쳐 쓰기보다 새로 만드는 쪽을 고민 중이라면 [홈페이지 리뉴얼 전에 점검할 일곱 가지](/insights/website-renewal-checklist/)를 먼저 확인해 보세요.

미래애드원 [홈페이지 제작·운영](/services/website/)은 초기 제작과 지속 운영 계약으로 나뉘고, 오픈 후 유지보수와 콘텐츠 수정이 운영 범위에 들어갑니다. 견적서에는 제공 범위·횟수·수정·보고 주기·VAT·계약 기간을, 계약서에는 수정 횟수와 계약 기간, 해지와 환불 조건을 적습니다. 운영 비용은 상담 후 견적으로 안내합니다.

## 자주 묻는 질문

### Q. 유지보수 계약 없이 필요할 때만 건별로 맡겨도 되나요?
수정할 일이 드물고 홈페이지로 문의를 거의 받지 않는다면 건별 의뢰도 방법입니다. 다만 보안 업데이트, 백업, 도메인 갱신은 고칠 일이 없어도 챙겨야 하므로 이 세 가지를 누가 맡을지는 따로 정해 두세요.

### Q. 만든 업체가 아닌 곳에 유지보수를 맡길 수 있나요?
관리자 계정과 파일, 호스팅 접근 권한을 넘겨받을 수 있다면 가능합니다. 다만 새 업체가 구조를 파악하는 데 시간이 걸리니, 인수 점검 비용이 따로 드는지 먼저 물어보세요.

### Q. 유지보수 계약에 검색 노출 관리도 들어가나요?
업체마다 다릅니다. 사이트맵 제출 같은 기술 관리가 들어가는지, 콘텐츠 작성이나 AI 검색 대응은 별도 계약인지 견적서에서 나눠 확인하세요. 검색 등록 순서는 [네이버 서치어드바이저 등록 가이드](/insights/naver-search-advisor-sitemap-setup/)에 정리해 두었습니다.
